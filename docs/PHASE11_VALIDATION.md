# Phase 11: scientific analysis and post-result critique

The deterministic runtime establishes observations and canonical measurements.
ResultSummary reads the current completed run, its run-scoped MetricRecords and
verified raw artifact before any model call. It preserves conditions, counts,
failures, missing-count lower bounds, primary and secondary outcomes, differences,
preregistered criteria, usage, actual-cost unknowns and provenance. Relative
comparisons are absent when the control value is zero. No inferential statistics
or canonical metrics are calculated by an LLM.

## Scientific contract and scope

The existing canonical ScientificAnalysis now has an explicit version, exact
hypothesis reference, metric IDs, evidence pins, criteria evaluation, claims,
confounder assessments and causal/generalization scope. Existing enum labels
remain SUPPORTED, PARTIALLY_SUPPORTED, NOT_SUPPORTED and INCONCLUSIVE. They are
scientific assessments, not proof or Planner acceptance. The optional legacy
numeric confidence field stays at its default zero, explicitly unspecified,
rather than inventing a quantitative confidence. No follow-up recommendations
are dispatched or generated by this Phase 11 implementation.

Structured success comparisons can provide control/intervention names, metric
direction and a minimum improvement. Positive minima are inclusive; a zero
minimum requires a strictly positive improvement. A structured falsification
comparison can specify maximum_improvement=0. The tiny scalar protocol's exact
preregistered textual comparisons are also supported. Unknown textual criteria
or direction remain unresolved and require an inconclusive assessment. This
is a bounded descriptive interpreter, not a general natural-language criteria
solver or statistics package. Fixture values never appear in production logic.

AnalysisService reuses Phase 10 valid_result and rechecks exact hypothesis,
spec, run, metric fingerprints and original raw hash before reasoning and
under the commit lock. Later scientific versions invalidate the analysis,
even if an old selection event still references a prior version. Concurrent
scientific writes reject publication; invalid outputs never become canonical
analyses or reviews. Failed model calls preserve already completed records and
emit failure events. Normal pytest makes no model/network calls.

The analyst is an Omnigent role configured with gpt-6.1-sol/high. It receives
bounded charter, exact hypothesis/spec, deterministic result evidence,
representative observations from both conditions, current implementation
validation and separately labeled historical planning notes. Resource metadata
is summarized rather than dumping resource contents. Hypothesis, resource,
implementation and audit IDs may be referenced only when actually supplied.
Important numeric claims can map metric IDs to their exact measured values.
No post-hoc canonical metrics are created.

## Independent critique and bounded revisions

The existing Scientific Critic, also gpt-6.1-sol/high through Omnigent, reviews
analyses independently. It checks arithmetic claims, metric direction, criteria,
failures/denominators, sample adequacy, hypothesis discrimination, all secondary
outcomes, confound control, exploratory labeling, causality and scope.

Deterministic scientific guards flag clear proof/universal overclaims, invented
statistics/numbers, reversed metric direction, absent limitations/traceability,
unassessed preregistered confounders, ignored failures and omitted secondary
outcomes. These are conservative phrase/structured checks, not a complete
natural-language entailment verifier. Independent semantic critique remains
mandatory. A PASS cannot override unresolved deterministic findings or high
severity material issues. The software never manufactures a Critic verdict.

PASS, REVISE and REJECT remain canonical ReviewRecord verdicts. REVISE permits
one Analyst response/revision and one final Critic review. Each material issue
requires ACCEPT, REBUT or CLARIFY with a concise reason; rebuttals require real
evidence references. Both analysis versions and all reviews/responses remain
append-only. REJECT or unresolved final REVISE returns Planner control while
preserving disagreement. Reinvoking critique on an already reviewed version
cannot extend the loop. The Critic cannot write measurements, raw artifacts,
experiments or hypotheses.

SQLite schema v3 adds a composite analysis identity (analysis_id, version).
The transactional v1/v2 migration preserves legacy analysis JSON and reviews
verbatim; missing additive fields default on deserialization. Historical
analysis labels without current pins and a trusted creation receipt do not
authorize downstream decisions. No new table was introduced.

## Orchestration and freshness

A matching, unsuperseded persisted ANALYZE_RESULT route invokes Analyst and
Critic, or Critic alone on an existing current analysis. Dispatch is recorded
once under lock and ends with SPECIALIST_COMPLETED. No next action executes.

Valid result without analysis derives ANALYSIS; pending critique derives
ANALYSIS_REVIEW; initial REVISE returns ANALYSIS; final PASS/REJECT or unresolved
final revision returns ADAPTIVE_DECISION. Stale interpretation returns Planner
reassessment. RUN_FOLLOWUP, ACCEPT_HYPOTHESIS and result-based REJECT_HYPOTHESIS
require current PASS-reviewed analysis; acceptance additionally requires a
supportive assessment. Pre-result rejection of a proposed hypothesis remains
available. PlannerContext includes exact identities/versions, measurements,
assessment, verdict, freshness, findings, limitations and unresolved confounders,
without raw dumps. The Planner owns the next scientific action.
